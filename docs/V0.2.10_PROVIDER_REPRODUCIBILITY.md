# v0.2.10 — Semantic Provider Reproducibility

Status: **WAVE 3 CANDIDATE / STACKED ON SKILLS PR #9**

## Goal

Prevent new compiler evaluations from depending on an implicit historical model
default and make every model-backed benchmark reproducible enough to audit.

## SemanticProviderConfig

New v0.2.10 runtime code requires an explicit model identifier.

Environment entrypoint:

- `PAC_SEMANTIC_MODEL` — required;
- `PAC_SEMANTIC_PROVIDER` — optional provider label, defaulting only to the
  transport family `openai-responses`, not to a model.

If `PAC_SEMANTIC_MODEL` is missing or empty, configuration fails with
`semantic_model_required`.

`build_configured_provider(...)` always passes the configured `model_id`
explicitly to the provider constructor. The recovered v0.2.9 provider remains
unchanged and frozen.

## EvaluationRunManifest

Each evaluation run can now record:

- run id;
- provider;
- exact model id;
- policy version;
- case-set id and SHA-256;
- prompt SHA-256;
- schema SHA-256;
- SDK version;
- request parameters;
- timezone-aware start/completion timestamps;
- response ids;
- usage metadata.

Timestamps are explicit inputs. The manifest does not invent wall-clock time,
which keeps tests and replay deterministic.

## Boundary

This wave does not execute a model-backed benchmark and does not expose a blind
holdout. It only creates the configuration and evidence contracts required for
a future authenticated evaluation.

## Regression

The RED failed because the v0.2.10 provider configuration modules did not
exist. After implementation, full project regression run #38 passed with
91 current-tree tests.
