# v0.2.10 — Automatic ExecutionGraph Compiler

Status: **WAVE 8 CANDIDATE / STACKED ON REGISTRY POLICY PR #14**

## Goal

Remove repetitive manual ExecutionPlan construction while preserving the
semantic decisions already made by the policy.

## Graph compilation

ExecutionGraphCompiler consumes:

- active PatternRegistry decisions;
- policy-emitted quality gates;
- explicitly declared required and optional runtime capabilities;
- objective and success definition.

It compiles generic phases only when needed:

```
prepare -> execute -> verify -> independent-review
```

Rules:

- prepare exists only when active patterns declare prerequisites;
- execute always exists;
- verify exists only when policy emitted one or more gates;
- independent-review exists only when policy emitted
  INDEPENDENT_REVIEW_GATE.

The compiler does not add registry default gates that the policy did not emit,
preventing a silent behavior change.

## Artifacts

PatternRegistry produced_artifacts become ArtifactContracts.

Pattern prerequisites produce a separate prerequisites ArtifactContract so
ExecutionSpecV2 validation can trace every node output to a declared artifact.

## Capabilities

Required runtime capabilities are attached explicitly to the execute node and
to the ExecutionPlan. Optional capabilities remain optional.

No capability is inferred as available from task wording.

## Canonical runtime

CanonicalCompilerRuntime.compile_auto(...) now performs:

request -> semantic provider -> policy -> graph compiler -> capability
resolution -> ExecutionSpecV2

The provider and policy are each executed once.

## Regression

The RED failed because ExecutionGraphCompiler did not exist. After the minimum
implementation, Full project regression run #59 passed with 133 current-tree
tests and the recovered public-safe baseline remained green.
