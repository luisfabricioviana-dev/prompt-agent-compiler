# v0.2.10 — Guarded REA ReleaseNode

Status: **WAVE 6 CANDIDATE / STACKED ON CANONICAL RUNTIME PR #12**

## Purpose

Connect an approved ExecutionSpecV2 artifact to the existing signed REA bridge
without equating compiler readiness with release authorization.

## Required gates before delegation

The ReleaseNode delegates to REA only when:

1. ExecutionSpecV2 readiness is exactly READY;
2. ReviewerSpec evaluation produced PASS;
3. `rea.release` is a mandatory runtime capability and is AVAILABLE;
4. the requested artifact id exists in the ExecutionSpecV2 artifact contracts;
5. non-empty immutable bytes are supplied.

If any condition fails, the node returns BLOCKED before the REA runner is
invoked.

## Dispatch boundary

Dispatch is disabled by default.

When `enable_dispatch=True`, a separate `release_approved=True` input is
required. The flag cannot be smuggled through `rea_kwargs`.

The node does not synthesize:

- credentials;
- signing keys;
- provenance statements;
- release authorizations;
- destination identity;
- observers.

Those remain caller/runtime boundary inputs to the existing fail-closed REA
bridge.

## Failure behavior

Exceptions from the REA runner fail closed as `rea_release_runner_failed`.
A non-PipelineResult response is rejected.

The underlying REA pipeline remains responsible for destination-bound signed
authorization, single-use claim persistence, dispatch state, signed observer
evidence, and reconciliation.

## Scope limit

This wave does not provide a real publisher, production key custody, effective
token-scope proof, or distributed exactly-once delivery.
