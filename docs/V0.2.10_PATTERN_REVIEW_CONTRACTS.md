# v0.2.10 — Pattern and Review Contracts

Status: **WAVE 4 CANDIDATE / STACKED ON PROVIDER PR #10**

## PatternDefinition

P01–P08 now have declarative contracts separate from the recovered scoring
implementation. Each PatternDefinition can declare:

- activation features;
- blocking features;
- prerequisites;
- required capabilities;
- produced artifacts;
- default quality gates;
- failure routes;
- complexity cost.

The default registry contains exactly P01 through P08. This wave does not yet
replace recovered v0.2.9 scoring with the registry; migration remains a
separate behavior change.

Notable defaults:

- P05 OPTIMIZE requires a measurable baseline/proxy and carries
  BASELINE_GATE + REGRESSION_GATE.
- P07 MULTI_AGENT carries INDEPENDENT_REVIEW_GATE.
- P08 PRODUCTION_UI carries ACCESSIBILITY_GATE + RESPONSIVE_GATE.

## ReviewerSpec

ReviewerSpec is an executable review contract. A review can PASS only when:

- every required gate is represented;
- every required gate passes;
- every passing required gate has evidence;
- independent review is confirmed when required.

FAIL returns:

- failed gates;
- reasons;
- targeted repair actions;
- targeted reverification scope.

The executor's own success claim is not sufficient review evidence.
