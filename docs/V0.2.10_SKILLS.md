# v0.2.10 — Agent Skills

Status: **WAVE 2 CANDIDATE / STACKED ON RUNTIME CONTRACTS PR #8**

## Implemented skills

- `compile-execution-spec`
- `review-execution-spec`
- `repair-failed-run`
- `evaluate-compiler`
- `governed-release`

Each Skill is stored as `skills/<name>/SKILL.md` with explicit name and
description frontmatter.

## Boundary

Skills describe reusable workflows. They do not manufacture runtime facts.

- Capability availability comes from `CapabilityRegistry`.
- Execution readiness comes from `ExecutionSpecV2`.
- Model/provider access stays behind the semantic provider boundary.
- External authentication and write operations stay at controlled runtime,
  connector, MCP, or destination-adapter boundaries.
- Release signing material is never embedded in a Skill.

## Safety properties

`compile-execution-spec` must preserve UNKNOWN capability state and cannot
silently treat it as available.

`review-execution-spec` requires quality-gate and artifact evidence and
supports independent review rather than executor self-approval.

`repair-failed-run` starts from causal attribution and minimum repair scope,
then performs targeted reverification.

`evaluate-compiler` uses stable `case_id` identity, separates INTERPRETER and
POLICY errors, and never uses a blind holdout for tuning after observation.

`governed-release` remains opt-in, fail-closed and dry-run by default. Green CI
is not publication evidence. Confirmed delivery requires signed reconciliation.
