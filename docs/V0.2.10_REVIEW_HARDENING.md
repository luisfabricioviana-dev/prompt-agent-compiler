# v0.2.10 — Bounded Review Hardening

Status: **WAVE 11 CANDIDATE / STACKED ON PACKAGING PR #17**

A bounded review of the v0.2.10 stack identified three Important defects.

## 1. Semantic validation boundary

The recovered v0.2.9 policy validates NormalizedTask before routing.
RegistryAwarePolicyCompiler initially omitted that validation.

Fix:

- added `contracts.semantic_task_contract`;
- mirrors the recovered allowed-value and cross-field semantic rules;
- remains installable without importing `recovered_v0_2_9`;
- RegistryAwarePolicyCompiler now validates before scoring/routing.

This restores fail-closed behavior for invalid normalized semantics.

## 2. Independent-review causal ordering

ExecutionGraphCompiler initially placed
`INDEPENDENT_REVIEW_GATE` on the generic verify node and then again on a
separate independent-review node.

Fix:

- generic verify receives only non-independent gates;
- if independent review is the only gate:
  `execute -> independent-review`;
- if other gates exist:
  `execute -> verify -> independent-review`.

The independent-review gate is evaluated exactly in the phase that can
actually produce independent-review evidence.

## 3. Optional REA bridge packaging boundary

The installable distribution contains `contracts*` only. ReleaseNode
initially imported the top-level `rea_signed_release_bridge` in its
constructor, so an installed package could import ReleaseNode but fail to
instantiate it outside the repository checkout.

Fix:

- the optional bridge is lazy-loaded at execute time;
- constructor remains usable in the contracts-only distribution;
- missing bridge returns fail-closed
  `rea_release_runner_unavailable`;
- injected release runners retain existing behavior.

CI now instantiates ReleaseNode from `/tmp` after package installation.
