# v0.2.10 — Canonical Compiler Runtime

Status: **WAVE 5 CANDIDATE / STACKED ON PATTERN+REVIEW PR #11**

## Canonical composition

The v0.2.10 runtime now has a single composition boundary:

```
request
  -> semantic provider
  -> deterministic policy compiler
  -> pattern registry validation
  -> capability registry resolution
  -> ExecutionSpecV2
  -> ReviewerSpec (when requested)
```

The runtime does not choose a model and does not inspect provider credentials.
Those concerns remain in provider configuration/runtime boundaries.

## Safety invariants

- The raw request emitted by the policy must match the input request exactly.
- Every policy-emitted pattern id must exist in PatternRegistry.
- Every capability required by an execution node must be declared by the plan
  or legacy capability contract.
- Missing required runtime capabilities remain UNKNOWN and produce
  `UNKNOWN_CAPABILITY`; they are never promoted to AVAILABLE.
- The runtime does not enable REA dispatch.
- PatternRegistry validates identity in this wave; recovered policy scoring is
  not yet rewritten around declarative PatternDefinition.

## Review compilation

`reviewer_spec_from_execution(...)` derives:

- required gate identities;
- target artifact ids;
- original objective and constraints;
- critical assumptions;
- optional adversarial/regression/evidence review requirements.

A quality gate without a stable identity is rejected instead of silently
disappearing from the review.

## Regression
