# v0.2.10 — Release Authority Coverage Hardening

Status: **WAVE 12 CANDIDATE / STACKED ON REVIEW HARDENING PR #18**

## Evidence-driven target

After Wave 11, the global contracts statement-line proxy was healthy, but
`contracts/rea_release_authority.py` was the only critical outlier at 53.12%.

Because this module authenticates release authority, a global average was not
considered sufficient protection.

## Direct adversarial tests

Dedicated tests now cover both authorization formats:

- legacy artifact-bound `REA-RELEASE-v1`;
- destination-bound `REA-RELEASE-DEST-v2`.

The suite verifies:

- valid HMAC authorization;
- short/invalid trust key rejection;
- issuer mismatch;
- malformed release id;
- malformed artifact digest;
- digest mismatch;
- malformed signature;
- forged signature;
- invalid destination identity;
- destination-specific signature binding;
- wrong authorization object type.

No cryptographic or authorization behavior was changed.

## Critical-file coverage gate

The stdlib statement-line coverage proxy now supports fail-closed per-file
minimums in addition to the global minimum.

Current critical minimum:

`contracts/rea_release_authority.py >= 90%`

Observed in Full project regression run #82:

- current-tree tests: 163/163 PASS;
- release authority statement proxy: **100.0%**;
- global contracts statement proxy: **88.53%**;
- global blocking minimum: 85%;
- recovered public-safe v0.2.9: PASS.

The critical-file gate fails if the file disappears from the report or drops
below its configured threshold.
